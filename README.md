# Student Performance Overfitting Analysis

## 1. Problem Statement

An online-learning model performs exceptionally well on training students but much worse on new students. This project implements a simple neural network using training and unseen student data, compares both sets of results, and determines whether the behavior indicates overfitting.

## 2. Objective

To demonstrate overfitting in a controlled, reproducible student-performance classification experiment. The model predicts `0 = At Risk` or `1 = Good Performance` and is evaluated separately on students it trained on and students it never saw during training.

## 3. Concept Used

**Overfitting** occurs when a model learns the training examples too specifically, including noise, and consequently does not generalize well to unseen examples. Evidence includes a high training accuracy, lower test accuracy, continuously falling training loss, and increasing test loss.

## 4. Dataset Description

The project creates 300 realistic synthetic student records with a fixed seed (`42`). The seven input features are:

- `study_hours`
- `attendance`
- `previous_score`
- `assignment_score`
- `online_learning_hours`
- `quiz_score`
- `sleep_hours`

The target column is `performance`. Labels are based on a hidden academic-performance rule plus limited random variation representing real factors that are not measured (for example, health or internet access). This makes the classification task meaningful while allowing the high-capacity network to memorize training-specific noise.

## 5. Methodology

1. Generate and save the dataset as `data/students.csv`.
2. Split it reproducibly into 80% training students (240) and 20% genuinely unseen test students (60), using stratification.
3. Fit `StandardScaler` on training features only, then use it to transform the test features. This avoids data leakage.
4. Train the neural network for 500 epochs using Adam and `CrossEntropyLoss`.
5. Measure training and test loss/accuracy after every epoch. Test data is never used to update weights.
6. Save curves, a test confusion matrix, and an automatically generated conclusion.

## 6. Neural Network Architecture

```text
7 input features
       ↓
Linear(7, 64) → ReLU
       ↓
Linear(64, 32) → ReLU
       ↓
Linear(32, 2)
       ↓
Prediction: At Risk / Good Performance
```

## 7. Training Process

The implementation uses PyTorch, Adam with learning rate `0.01`, and 500 epochs. The network is intentionally sufficiently flexible for this small, noisy dataset, making the overfitting pattern observable. A fixed random seed controls data generation, splitting, and PyTorch initialization.

## 8. Evaluation Metrics

- **Accuracy:** percentage of correct predictions.
- **Cross-entropy loss:** how far predicted class probabilities are from true labels.
- **Generalization gap:** `training accuracy − test accuracy`.
- **Confusion matrix:** counts correct and incorrect predictions for the unseen students.

## 9. Actual Results

Results from the completed run are:

| Measure | Value |
| --- | ---: |
| Training accuracy | 100.00% |
| Unseen test accuracy | 60.00% |
| Training loss | 0.0001 |
| Unseen test loss | 3.6681 |
| Generalization gap | 40.00 percentage points |
| Lowest test loss | 0.6178 at epoch 6 |

The source of truth and full automatic conclusion are in [`outputs/results.txt`](outputs/results.txt). These numbers are generated by the scripts, not hard-coded.

## 10. Overfitting Analysis

Yes, clear overfitting was detected. The model achieved 100.00% accuracy on the 240 training students but only 60.00% accuracy on the 60 unseen students, giving a 40.00 percentage-point gap. Test loss was lowest at epoch 6 and increased to 3.6681 by epoch 500, while training loss fell to 0.0001. This indicates that continued training learned training-specific patterns/noise instead of improving performance for new students.

## 11. Conclusion

The observed behavior indicates overfitting. Excellent training performance alone is not proof of a useful model: the much weaker performance on genuinely unseen students shows poor generalization. In practice, possible remedies include early stopping, a smaller network, more data, dropout, or weight regularization.

## 12. How to Run

Open this folder in VS Code. In its integrated terminal, preferably inside a virtual environment, run:

```bash
python3 -m pip install -r requirements.txt
python3 src/generate_data.py
python3 src/train_model.py
python3 src/evaluate_model.py
```

On a standard macOS terminal, the scripts automatically select Matplotlib's non-interactive `Agg` backend so graphs are saved without opening windows. The generated figures and report appear in `outputs/`.
